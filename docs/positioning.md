# 포지셔닝 & 비전

> 2026-08-08. 시장 조사 2건(국내 금융업 / GitHub OSS)과 실데이터 검증 결과에서만 도출.
> 근거 없는 문장은 넣지 않는다.

## 1. 한 문장

> **분석하기 전에 감사한다.**
> 모든 가계부 앱이 "네 데이터는 맞다"를 전제할 때, 우리는 그 전제부터 검증한다.

## 2. 이 포지션의 근거 — 셋 다 실측이다

### 근거 1. 데이터는 실제로 틀려 있다

내 1년치 뱅샐 데이터에서 오늘 나온 것:

| 발견 | 규모 |
|---|---|
| 수입/지출/순자산 산술 불일치 | **−1,136만원** (수입 881만 vs 지출 2,018만인데 순자산 1,539만 보유) |
| 이체를 수입·지출로 이중계상하면 | 509건 **912만원** 왜곡 |
| 지출이 음수로 저장되는 부호 함정 | 무시하면 저축률 **24,305%** 출력 |
| 환불(지출 타입 + 양수 금액) | 36건 **71만원**, 놓치면 오차 143만원 |

**핵심은 이것이다: 나는 오늘 이 데이터에서 세 번 틀렸다.** 이체, 부호, 환불.
전부 "그럴듯한 숫자"라 눈으로는 안 걸린다. 사람도 LLM도 매번 새로 밟는 함정이다.

→ 이게 **"코드로 못 박은 감사 규칙"이 필요한 이유**이자, 제품의 존재 이유다.

### 근거 2. 아무도 안 하고 있다 — 사업자도, 오픈소스도

| | 국내 금융업 | GitHub OSS |
|---|---|---|
| 데이터 완결성 감사 | **0곳** | **0개** |
| 살아있는 계좌의 유휴 현금 지적 | **0곳** (숨은돈찾기는 휴면계좌 = 죽은 돈만) | **0개** |
| 개인재무 MCP 서버 | — | **한국 0개** (awesome-mcp-korea 금융 8/8이 주식·공시) |
| 재사용 가능한 뱅샐 파서 | — | **0개** (PyPI/npm 없음, 최고 스타 5) |

마이데이터의 실제 상태는 부실하다 — 금융사 간 자산 미연동, 제공 정보 범위 제한,
사업자 계좌 미연동이 반복 지적된다. 그런데 뱅샐·토스·카카오페이 어디도
*"이 계좌 연동이 끊겼다", "미분류 N건이라 통계가 왜곡됐다"* 를 리포트하지 않는다.

### 근거 3. 그들은 구조적으로 못 한다

**(a) 이해충돌.** 뱅크샐러드의 수익모델은 대출·카드·보험 **중개 수수료**다.
"이 상품에서 저 상품으로 갈아타라"를 중립적으로 말할 인센티브가 없다.
우리는 무료 OSS라 **팔 게 없다.** 이건 기능이 아니라 구조의 차이다.

**(b) 클라우드 강제.** 마이데이터 사업자는 법적 요건상 100% 클라우드 전용이다.
로컬 실행이라는 선택지 자체가 없다.

**(c) 1년 벽.** 뱅샐 내보내기는 **요청일 기준 최근 1년치만, 기간 지정 불가**다.
즉 뱅샐 자신도 장기 시계열을 사용자에게 못 준다.
**주기적으로 받아 축적하는 것 말고는 방법이 없고, 그건 사용자 쪽에서만 가능하다.**

## 3. 무엇을 하지 않는가 — 경계가 정체성이다

| 안 한다 | 이유 |
|---|---|
| **자문(advisory)** | 사실·계산·비교까지. 처방은 안 한다. 개인화 자문 + 대가 = 투자자문업 인가 영역 (`product.md` §5) |
| **유료화** | 위와 한 몸이다. 유료화하는 순간 규제 영역으로 넘어간다 |
| **우리 서버에 데이터 보관** | 차별점(b)을 스스로 버리는 일. 유저 로컬 + 유저 개인 Drive만 |
| **구독 감사를 핵심으로 내세우기** | 카카오페이 AI코치가 2026-08-04 베타 출시. 4,000만 사용자 기반과 정면 승부는 진다 |
| **뱅샐 대체** | 우리는 수집을 안 한다. 뱅샐이 모은 걸 검증한다. **보완재다** |
| **"LLM에 연결"을 차별점이라 부르기** | 후잉가계부 MCP가 이미 있다. 연결은 흔하다. **감사 로직이 차별점이다** |

## 4. 타겟

**1차: 나 자신 (dogfooding).** 실제로 매달 쓰지 않으면 규칙이 좋은지 알 수 없다.

**2차: 자기 돈이 어디서 새는지 궁금하고, 앱이 주는 요약을 못 믿는 사람.**
개발/오픈소스 경험이 있으면 지금 바로 쓸 수 있고, `.mcpb` 원클릭 설치가 붙으면 더 넓어진다.

명시적으로 **아닌** 사람: 예산 세우고 지키는 게 목적인 사람 (→ 카카오페이 AI코치, Actual Budget).
우리는 예산 도구가 아니다.

## 5. 비전 — 3단계

### 1단계. 감사 (지금)
뱅샐 내보내기 하나를 던지면 **"네 데이터에 이런 문제가 있다"** 를 짚는다.
수입 누락, 이중계상, 미분류, 환불 왜곡, 유휴 현금.
→ 성공 기준: **내가 매달 실제로 돌린다.**

### 2단계. 축적
뱅샐이 못 주는 것 — 1년을 넘는 시계열.
스냅샷을 쌓아 "지난달 대비", "6개월째 놀고 있는 잔고", "목표 대비 지금 어디"를 만든다.
→ 성공 기준: **1년 넘는 데이터가 쌓여 뱅샐로는 못 보는 질문에 답한다.**

### 3단계. 신뢰 계층
데이터 소스를 뱅샐에 한정하지 않는다. 어떤 앱을 쓰든, 어떤 형식이든
**"이 금융 데이터를 믿어도 되는가"** 에 답하는 계층이 된다.
→ 성공 기준: **남이 자기 데이터 소스를 붙여서 쓴다.**

## 6. 성공 지표 — 다운로드 수가 아니다

| 단계 | 지표 |
|---|---|
| 1 | 내가 3개월 연속 돌렸는가 |
| 1 | 리포트가 **내가 몰랐던 것**을 짚었는가 (알던 걸 재확인하는 건 실패) |
| 2 | 축적된 시계열이 1년을 넘겼는가 |
| 3 | 뱅샐 아닌 데이터 소스가 붙었는가 |

## 7. 정직한 리스크

| 리스크 | 성격 |
|---|---|
| **뱅샐 종속** | 내보내기 포맷이 바뀌거나 export가 막히면 죽는다. 완화: 헤더 불일치 시 즉시 실패(구현됨), 원본 zip 보존 |
| **xlsx 암호화 변형** | 타 프로젝트는 `msoffcrypto`로 xlsx를 푼다. 우리 파일은 평문이었다 — **두 변형이 공존한다** |
| **수동 트리거** | 뱅샐 내보내기는 유저가 앱에서 눌러야 한다. 완전 자동화는 원천 불가 |
| **선행 주자** | `Gyu-bot/my_ledge`가 거의 동일한 기획으로 활발히 개발 중(2026-07). 라이선스 없어 코드 차용 불가, 설계 참조만 |
| **대기업 추격** | 카카오페이가 완결성 감사를 붙이면 사용자 기반에서 밀린다. 방어선은 **로컬 + 이해충돌 없음** 뿐 |
| **뱅샐 토핑+** | 2025-01 혁신금융 지정 후 **1년 7개월째 미출시**. 시간은 있지만 무한하지 않다 |

## 8. 한 문단 요약

> 마이데이터는 데이터를 모아줬지만, 그 데이터가 맞는지는 아무도 검증하지 않는다.
> money-audit은 뱅크샐러드가 내보낸 데이터를 **분석하기 전에 감사한다** —
> 누락된 수입, 이중계상된 이체, 왜곡된 환불, 놀고 있는 현금을 짚는다.
> 로컬에서 돌고, 아무것도 팔지 않으며, 그래서 중립적일 수 있다.
> 그리고 뱅샐이 1년치만 주는 데이터를 사용자 손에 축적한다.
