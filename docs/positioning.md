# 포지셔닝 & 비전

> 2026-08-08. 시장 조사 2건(국내 금융업 / GitHub OSS)과 실데이터 검증에서만 도출.
> **개정 이력**: 초안은 "감사(audit)"를 전면에 세웠으나, 감사는 **경쟁력이 아니라 기본**이라는
> 판단에 따라 위생 요건으로 내리고 타겟 고객과 문제를 앞에 세웠다.

## 1. 타겟 고객

> **LLM은 익숙한데 돈 관리는 처음인 사회 초년생.**

- ChatGPT·Claude를 매일 쓴다. AI에게 물어보는 게 자연스럽다
- 최근 자산관리에 관심이 생겼다 (첫 직장, 첫 목돈, 주변의 "1억" 이야기)
- 금융 지식은 얕고, 앱이 주는 요약은 무슨 뜻인지 잘 모른다

**핵심 간극**: 이들은 이미 AI에게 뭐든 물어보지만, **자기 실제 금융 데이터로는 못 물어본다.**
"ChatGPT한테 물어보면 되지 않나?" 는 맞는 직감인데, 데이터를 못 물려서 일반론만 돌아온다.

명시적으로 **아닌** 사람: 예산 세우고 지키는 훈련이 목적인 사람 (→ 카카오페이 AI코치, Actual Budget).

## 2. 타겟 문제

**P1. "30세에 1억이라는데, 어떻게 모으는지 모르겠다."**
목표는 있는데 자기 상황에서 그게 가능한 숫자인지, 매달 얼마를 어떻게 해야 하는지 모른다.
검색하면 일반론만 나온다. 자기 숫자로 계산해주는 곳이 없다.

**P2. "내 소비 패턴을 보고 현실적인 피드백을 받고 싶다."**
월말에 "이번 달 식비 32만원" 같은 요약은 받는데, 그래서 뭘 어떻게 하라는 건지 모른다.
그리고 알림은 **늦게** 온다 — 다 쓰고 난 뒤에야 알려준다.

## 3. 약속 (Value Proposition)

> **"1억, 진짜로 가능한지 네 숫자로 알려준다."**
> 목표를 세우면 실제 소비·저축 패턴으로 도달 시점을 계산하고,
> 페이스가 어긋나면 알려준다. 그리고 왜 그런지 **물어볼 수 있다.**

세 층으로 구성된다:

| 층 | 무엇 | 주기 |
|---|---|---|
| **목표** | 1억까지 얼마 남았고, 현재 페이스면 언제 도달하는가 | 갱신 시 |
| **페이스** | 이번 달/주 소비가 목표 대비 어디쯤인가 | 주 1회 (→ 향후 일 단위) |
| **대화** | "왜 이번 달은 초과했어?" "이거 줄이면 얼마나 빨라져?" | 언제든 |

**세 번째가 다른 앱이 못 주는 것이다.** 나머지는 형태만 다를 뿐 경쟁자도 한다.

## 4. 기본 (Hygiene) — 내세우지 않지만 없으면 안 되는 것

### 데이터 감사

**차별점이 아니다. 조용히 돌아가는 위생 층이다.**

그러나 없으면 제품이 성립하지 않는다 — 실측 데이터에 **−1,136만원 산술 불일치**가 있고,
이 상태로 "1억까지 8,461만원 남았습니다"를 말하면 **틀린 숫자로 인생 계획을 세우게 만든다.**

오늘 실제로 밟은 함정 (전부 그럴듯한 숫자라 눈으로 안 걸림):

| 함정 | 놓치면 |
|---|---|
| 이체를 수입·지출로 이중계상 | 509건 **912만원** 왜곡 |
| 지출이 음수로 저장 | 저축률 **24,305%** 출력 |
| 환불 = 지출 타입 + 양수 금액 | 36건, 오차 **143만원** |

→ 원칙: **조용히 검증하고, 이상할 때만 말한다.** 리포트 첫 줄이 감사 결과여선 안 된다.

## 5. 왜 우리인가 — 구조적 차별 셋

기능은 복제된다. 구조는 안 된다.

**(a) 자유 대화 (LLM 네이티브)**
카카오페이 AI코치는 영역별 특화 에이전트가 협업하는 구조이고, 총괄이 밝힌 설계 의도가
*"요구되는 모델 체급이 낮은 대신 도메인 정확도는 올라간다"* 이다.
정해진 도메인 밖의 질문에는 약할 수밖에 없다.
⚠️ **자유 대화 인터페이스 제공 여부는 미확인** — 실제 앱 확인 필요. 여기가 갈림길이다.

**(b) 데이터 소유**
우리는 유저가 파일을 갖는다. 앱을 지워도 데이터가 남고, 다른 도구로 옮길 수 있다.
마이데이터 사업자는 법적 요건상 서버 처리이며 로컬이라는 선택지 자체가 없다.
그리고 뱅샐 내보내기는 **최근 1년치만, 기간 지정 불가** — 장기 시계열은 사용자 손에서만 쌓인다.

**(c) 팔 게 없다 — 가장 강한 축**

기존 서비스는 **어딘가에서 반드시 수익화 지점을 보여야 한다.**

| 서비스 | 수익화 지점 = 유저가 느끼는 피로 |
|---|---|
| 뱅크샐러드 | 대출·카드·보험 **중개 수수료** → 상품 추천이 계속 뜬다 |
| 카카오페이 | *"규제 정합성이 확보되는 순서대로"* **투자권유까지 확대 예고** |
| 무료 가계부 앱 | 광고 |
| 로보어드바이저 | 일임·자문 수수료 (핀트: 수익금의 연 9.5%) |

**우리는 파이프라인을 만들어 배포할 뿐이라 그 지점이 없다.**
"이 카드로 갈아타세요"도, "이 예금이 유리합니다(제휴)"도 없다.
**권유 자체가 없다.**

이건 부수 효과가 아니라 **제품의 정직성을 담보하는 구조**다.
"현금 비중 94%입니다" 라고 말할 때, 그 뒤에 팔 상품이 없다는 걸 유저가 알 수 있다.

> **사이드프로젝트라는 게 약점이 아니라 강점이다.**
> 성장 압력이 없으니 유저를 쥐어짤 이유가 없다. MAU를 올릴 필요도,
> 체류시간을 늘릴 필요도, 알림을 더 보낼 필요도 없다.

**단, 정직한 대가**: 지속성 리스크. 유지보수가 멈추면 뱅샐 포맷 변경 시 죽는다.
완화책은 OSS라는 것뿐이다 — 남이 이어받을 수 있다.

## 6. 무엇을 하지 않는가

| 안 한다 | 이유 |
|---|---|
| **자문(advisory)** | 사실·계산·비교까지. 처방은 안 한다. 개인화 자문 + 대가 = 투자자문업 인가 영역 |
| **유료화** | 위와 한 몸. 유료화하는 순간 규제 영역 |
| **우리 서버에 데이터 보관** | 차별점 (b)를 스스로 버리는 일 |
| **감사를 전면에 내세우기** | 사용자가 원하는 건 목표 달성이지 데이터 품질이 아니다 |
| **예산 훈련 도구** | 카카오페이 AI코치의 자리다. 우리는 목표·자산 쪽 |
| **뱅샐 대체** | 수집은 안 한다. 뱅샐이 모은 걸 쓴다. **보완재다** |

## 7. 비전 — 3단계

### 1단계. 목표와 페이스 (지금)
목표를 세우고, 실제 데이터로 도달 시점을 계산하고, 주 단위로 페이스를 알려준다.
그리고 무엇이든 물어볼 수 있다.
→ 성공 기준: **내가 매달 실제로 돌린다. 그리고 리포트가 내가 몰랐던 걸 짚는다.**

### 2단계. 실시간
카드사 SMS·결제 알림을 받아 당일 지출을 누적한다 (`crow-backend`(MIT) 참고 가능).
"오늘 3만원 썼고, 이 페이스면 이번 달 15만원 초과" 가 가능해진다.
→ 뱅샐만으로는 **구조적으로 불가능**하다. 별도 데이터 소스가 필요하다.
→ 성공 기준: 알림을 끄지 않고 계속 쓴다.

### 3단계. 데이터 소스 개방
뱅샐에 한정하지 않는다. 어떤 앱·형식이든 붙여 쓸 수 있게 한다.
→ 성공 기준: 남이 자기 데이터 소스를 붙인다.

## 9. 정직한 리스크

| 리스크 | 성격 |
|---|---|
| **카카오페이가 이 방향으로 온다** | 자산 분석·관리 → 투자까지 확대 예고. 4,000만 사용자 기반. **방어선은 (a)(b)(c) 뿐** |
| **차별점 (a)가 미확인** | AI코치가 자유 대화를 이미 지원하면 (a)가 사라진다. **확인이 급하다** |
| **뱅샐 종속** | 포맷 변경·export 중단 시 죽는다. 완화: 헤더 불일치 시 즉시 실패(구현됨), 원본 보존 |
| **수동 트리거** | 뱅샐 내보내기는 유저가 눌러야 한다. 완전 자동화 원천 불가 |
| **선행 주자** | `Gyu-bot/my_ledge` 거의 동일 기획, 2026-07까지 활발. 라이선스 없어 설계 참조만 가능 |
| **xlsx 암호화 변형** | 타 프로젝트는 `msoffcrypto`로 xlsx를 푼다. 우리 파일은 평문 — 두 변형 공존 |

## 10. 한 문단 요약

> 사회 초년생은 이미 AI에게 뭐든 물어보지만, 자기 금융 데이터로는 못 물어본다.
> k-money은 뱅크샐러드가 내보낸 실제 데이터를 물려서 **"1억까지 얼마나 남았고,
> 지금 페이스면 언제 도달하는지"** 를 계산하고, 어긋나면 알려주고, 무엇이든 물어보게 한다.
> 데이터는 유저가 파일로 소유하고, 우리는 아무것도 팔지 않는다.
> 그 숫자가 맞는지는 뒤에서 조용히 검증한다.
