### A12 — 경계는 어디인가 (2026-08-08 적대적 검토로 재정의)

에이전트 4명(원칙·삭제·보존·유즈케이스 역산)을 붙여 다시 그었다. 개발자가 **계속 계산을 코드로 미는 경향**을 보였고 사용자가 세 번 제지했는데, 그게 우연이 아니라 계통 오차였다.

> **우리가 파는 건 산수가 아니라 "어떤 식을 쓸지"다.**

| 물어볼 것 | 답이 예면 |
|---|---|
| 원본 행을 훑어야 나오는가? (그룹핑·중앙값·정렬) | **넣는다.** LLM이 할 수 없다 |
| 그럴듯한 식이 여럿인데 하나만 맞는가? | **넣는다.** 틀린 식이 조용히 통과한다 |
| 대화 한 세션이 원리적으로 모르는가? (이전 스냅샷) | **넣는다** |
| 식이 하나뿐인가? (뺄셈·나눗셈 한 번) | **뺀다.** LLM이 한다 |
| 이 값을 정의하는 상수를 **우리가** 골랐는가? | **뺀다.** 집계가 아니라 판단이다 |

**분기점은 "코드 vs LLM"이 아니라 "순회 vs 선택"이다.** 상수가 순회를 게이팅하면(`recurring`의 band 0.25) 취향이어도 남는다 — 순회 자체를 LLM이 못 하기 때문이다. 상수가 **출력 그 자체**면(goalTable의 1억, cash의 3개월) 뺀다.

#### 방어 논거가 틀렸었다

"LLM이 나눗셈을 틀린다"로 방어했는데 **프런티어 모델은 순수 산수를 거의 안 틀린다** (MATH-211에서 Claude Sonnet 4가 100%). 진짜 근거는 따로 있다 — `pace`를 빼고 남은 필드로 만들 수 있는 그럴듯한 공식을 전수 조사하면:

```
−41,942/월  못 감   (수입 − 지출) ÷ (일수/30.44)
−44,900/월  못 감   (수입 − 지출) ÷ 12
−41,446/월  못 감   monthly[].net 평균
+334,043/월 236개월 + 이체 전체
+315,360/월 250개월 + external.net 만          ← 정답
```

**여섯 중 넷이 부호를 뒤집는다.** 산수는 맞고 **식이 틀린다.** 의미 계층을 줘도 정확도가 68%에서 멈춘다는 벤치마크가 있는데, 남은 32%가 정확히 이 실패다.

#### 반쯤 지우는 것이 가장 위험하다

`recurring.items[]`를 지우고 `activeMonthlyTotal`만 남기면 — `recurring`은 금액이 일정한 **모든 것**을 잡으므로 월세·식비가 섞인다:

```
총액만 주면   "고정지출 전액 끊으면 190개월 단축"
진짜 구독만    11개월 단축                        → 179개월(15년) 차이
```

`items[].label`이 실려야 LLM이 월세와 넷플릭스를 구분한다.

#### 절단은 반드시 밝힌다

목록을 자르면서 말을 안 하면, 합계를 검산한 LLM이 안 맞는 걸 보고 데이터를 못 믿거나 **없는 사실을 지어낸다.** 실측에서 카테고리 246,450원 · 계좌 45,629원 · 이체 상대 3,050,875원(유입의 28%)이 말없이 사라지고 있었다.

> 그리고 **못 믿을 값은 키 자체를 만들지 않는다** (`savingsRate`). null로 두면 인용되고, 없으면 인용될 수 없다. 우리는 유저의 프롬프트를 소유하지 않으므로 **파일 자체가 유일한 방어 수단**이다.

|---|---|---|
| "분석 전에 **감사**한다"를 전면에 | 감사는 **기본**으로 강등 | 사용자가 원하는 건 목표 달성 |
| 타겟 = **준개발자** | **사회 초년생** | Apps Script로 이탈 지점이 사라짐 |
| **플러그인** 중심 | **Apps Script + Drive 커넥터** | 웹·모바일이 로컬 MCP에 못 닿음 |
| **토스증권 Open API** 필요 | **불필요** | 뱅샐에 종목별 손익이 이미 있음 |
| **로컬 우선**(launchd) | **Drive 단일 진실 원천** | 로컬은 7일마다 재인증 → 자동화가 아님 |
| **V2 하이브리드** | **V1 완전 자동** | ZipCrypto 자체 구현으로 임계 경로가 열림 |
| **UnzipGs** | **직접 구현** | Rhino sunset |
| 설치 **5단계 10분** | **3조작** | GCP OAuth는 Apps Script에 불필요 |
| **"탭 3번"** / **"월 1회"** | 실제 6단계 / 유저가 정함 | 검증 없이 계승한 표현 |
| **(A9) Python 참조 구현 + Apps Script 포팅** | **순수 JS 한 벌 (A11)** | Python은 유저에게 한 번도 돌지 않는다. 포팅은 영구적인 이중 유지보수 |
| **감사 규칙 엔진 R1~R8** | **삭제. 집계까지만 (A12)** | 규칙의 가치는 문장이 아니라 계산 선택이었다 |
| **"Drive 커넥터는 19KB JSON을 빈 문자열로 읽는다"** | **틀린 기록** | 갓 만든 파일이 잠시 비어 보인 것. 크기·MIME 무관 |
| **문턱값 = 수입의 5%** | **지출의 5%** | 수입이 틀렸다고 말하는 지표가 그 수입으로 문턱을 잡으면 순환 |
| **goalTable · levers · suggestedHorizons** (`goal.js` 291줄) | **전부 삭제** | 유저 질문 25개 역산 시 **필요한 질문 0개.** 실측에서 goalTable의 etaMonths 3개가 전부 null, levers는 단 1바이트도 출력된 적 없음 |
| **복리 수익률 계산** | **삭제 — 이번엔 실제로** | 앞서 "걷어냈다"고 **선언만 하고 코드에 남겨뒀다.** 기본값 0이라 실데이터에서 안 터져 아무도 몰랐다 |
| **`cash.emergencyBuffer3m`** | **삭제** | "3개월"이 결론의 부호를 뒤집는다 (3개월→유휴 359만원 / 6개월→비상금 144만원 부족). 고용 형태에 따라 다르니 LLM이 정한다 |
| **"LLM이 나눗셈을 틀린다"** | **틀린 방어 논거** | 프런티어 모델은 순수 산수를 거의 안 틀린다. 틀리는 건 **식의 선택**이다 |
