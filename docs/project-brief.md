# k-money — 프로젝트 브리프

> 출처: claude.ai 웹 대화 (share/bbeebf45) 에서 확정된 내용을 옮김. 2026-08-08 기준.

## 무엇을 만드는가

개인 금융 데이터(증권 계좌 + 지출 내역)를 AI가 정기적으로 **감사(audit)** 해주는 도구.
"내 예수금이 놀고 있다", "이 고정지출이 새고 있다" 를 스스로 찾아서 리포트로 내놓는 것이 핵심 가치.

## 확정 사항

### 타겟
**개발 / 오픈소스 경험이 있는 청년.** ("준개발자")
- 비개발자 타겟은 폐기. 온보딩 시뮬레이션 결과 완주율 10% 미만으로 추정됨.
- 이 층에겐 설치가 3분이고, "플러그인 두 줄로 끝"이 그 자체로 홍보 문구가 됨.

### 배포 채널 — Tier 2로 확정
| | Tier 1 (스킬만) | **Tier 2 (플러그인 + MCP)** ← 확정 |
|---|---|---|
| 설치 | 0단계 | 3분 |
| 환경 | 웹·모바일 | 로컬 Claude Code |
| 입력 | 스크린샷 | API 자동 |
| 시크릿 | 불필요 | 필요 |

Tier 1은 **체험 경로**로 남겨둠 (버리지 않음). 웹으로 유입 → 플러그인으로 정착.

Tier 2를 고른 결정적 근거: 웹 챗 컨테이너는
1. 네트워크가 허용목록으로 제한돼 증권사 API 호출이 막히고,
2. 파일시스템이 휘발성이라 `.env`·토큰 캐시가 매번 날아가며,
3. 주문 권한 붙은 시크릿을 채팅창에 붙여넣는 건 애초에 나쁜 설계.

### 패키징 — 스킬이 아니라 **플러그인**
스킬이 MCP 서버와 함께 돌아야 작동하므로 스킬만으로는 배포 단위가 성립하지 않음.
플러그인 = 스킬 + MCP 서버 + 커맨드 + 훅을 묶는 컨테이너.

온보딩 happy path:
```
1. claude plugin marketplace add github.com/<you>/k-money
2. claude plugin install k-money
3. /reload-plugins
4. /set-up          ← 에이전트가 손잡고 진행
5. "내 계좌 감사해줘"
```
이 구조로 Python 설치 · `.env` 작성 · `claude_desktop_config.json` 편집 3개의 마찰점이 통째로 사라짐.

### ~~남는 마찰: 토스증권 키 발급~~ → **삭제됨 (2026-08-08)**

실제 뱅샐 내보내기를 파싱해보니 `5.투자현황` 섹션에 **종목별 투자원금·평가금액·수익률**이,
`3.재무현황`에 **계좌별 잔액**이 이미 다 들어 있었다. 이 서비스는 주문을 내지 않고
readonly 조회만 필요하므로 **토스증권 Open API는 불필요하다.**

이 결정으로 함께 사라지는 것:
- PC 웹(WTS) 로그인 → client_id/secret 발급 마찰 (온보딩 최대 이탈 지점이었음)
- 주문 권한이 붙은 자격증명을 다루는 위험 전체
- 증권사 MCP 서버

뱅샐 스냅샷에 **없는 것** (감사 범위를 넓힐 때 재검토):
- 예수금이 `기본계좌` / `종합_CMA` 로 뭉뚱그려짐 (종목과 구분은 되지만 상세는 없음)
- 매수/매도 **거래 내역** 없음 — 잔고와 손익만 있다. 매매 패턴 분석은 불가

### 남는 마찰: Gmail OAuth
Google Cloud 프로젝트 생성 → OAuth 클라이언트 발급 (`docs/setup-gmail.md`).
`gmail.readonly` 는 Google의 **제한된 범위**라 테스트 모드에서만 쓸 수 있고,
**refresh token 이 7일마다 만료**된다. `/set-up` 이 이걸 미리 알리고
`invalid_grant` 감지 시 재인증을 자동으로 띄워야 한다.

### `/set-up` 필수 요건 — 검증 단계
마지막에 **읽기 전용 호출**(계좌 목록 조회)을 날려 결과를 출력할 것:
```
✓ 연결됨 — 계좌 2개, 보유종목 7건
```
설치형 도구의 최대 이탈 지점은 *실패했을 때*가 아니라 *성공했는지 모를 때*.

### 보안 설계 (타협 불가)
에이전트가 `.env`를 대신 써준다 = **시크릿이 모델 컨텍스트를 통과한다.**
주문 권한이 붙은 증권 자격증명이므로 다음을 강제:

- `/set-up`은 키를 **받아적지 않는다.** 파일 경로만 안내하고 사용자가 직접 붙여넣게 하거나, OS 키체인에 저장.
- 저장 후 에이전트가 그 파일을 **다시 읽지 않도록** 스킬에 명시.
- `.gitignore` 등록과 파일 권한 `600`은 `/set-up`이 자동 처리.
- 마켓플레이스 배포는 **커밋 SHA로 핀.** 공급망 공격이 곧 계좌 접근.

## 데이터 소스

| 소스 | 경로 | 상태 |
|---|---|---|
| 토스증권 Open API | client_id/secret, MCP 서버 경유 | API 사용 가능 확인됨 |
| 뱅크샐러드 내보내기 | 암호 zip → 메일 수신 → 다운로드 → `unzip -P` → 엑셀 파싱 | **미검증** |
| 예적금 금리 | finlife (금감원 금융상품통합비교공시) | 웹 검색으로 조달 |

### 뱅샐 파이프라인 목표
```
[매월] 뱅샐에서 탭 3번 (파일로 받기)
[자동] /audit → 메일에서 zip 수신 → 해제 → 파싱 → 리포트
```
사용자 손이 닿는 건 뱅샐 탭 3번뿐. 이게 Tier 2의 **실질 차별점**이자 업그레이드 동기.
zip 비밀번호는 사용자가 직접 정하는 값이라 매번 동일하게 유지 가능 → 최초 1회만 state에 저장.
