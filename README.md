# k-money · 돈동생

> **자산 같이 봐주는 똑똑한 동생.**
>
> "1억까지 얼마 남았어?" 하고 물으면, 네 실제 데이터로 계산해서 답한다.
> 페이스가 어긋나면 알려주고, 왜 그런지 되물을 수 있다.
> 데이터는 네가 갖고, 우리는 아무것도 팔지 않는다.

| | |
|---|---|
| **repo · CLI** | `k-money` — 검색과 발견에 최적화 |
| **서비스명** | **돈동생** — 기억과 정서에 최적화 |

---

## 1. 누구를 위한 것인가

**LLM은 익숙한데 돈 관리는 처음인 사회 초년생.**

- ChatGPT·Claude를 매일 쓴다. AI에게 물어보는 게 자연스럽다
- 최근 자산관리에 관심이 생겼다 (첫 직장, 첫 목돈, 주변의 "1억" 이야기)
- 금융 지식은 얕고, 앱이 주는 요약은 무슨 뜻인지 잘 모른다

**핵심 간극**: 이미 AI에게 뭐든 물어보지만, **자기 실제 금융 데이터로는 못 물어본다.**
"ChatGPT한테 물어보면 되지 않나?"는 맞는 직감인데, 데이터를 못 물려서 일반론만 돌아온다.

### 해결하려는 문제

| | 문제 |
|---|---|
| **P1** | "30세에 1억이라는데, 어떻게 모으는지 모르겠다." 목표는 있는데 자기 상황에서 가능한 숫자인지 모른다. 검색하면 일반론만 나온다 |
| **P2** | "내 소비 패턴을 보고 현실적인 피드백을 받고 싶다." 월말 요약은 받는데 그래서 뭘 하라는 건지 모르고, 알림은 다 쓰고 난 뒤에 온다 |

**아닌 사람**: 예산 세우고 지키는 훈련이 목적인 사람 (→ 카카오페이 AI코치, Actual Budget).

## 2. 무엇을 해주나

| 층 | 무엇 | 주기 |
|---|---|---|
| **목표** | 1억까지 얼마 남았고, 현재 페이스면 언제 도달하는가 | 갱신 시 |
| **페이스** | 이번 달 소비가 목표 대비 어디쯤인가 | 주 1회 (→ 향후 일 단위) |
| **대화** | "왜 이번 달은 초과했어?" "이거 줄이면 얼마나 빨라져?" | 언제든 |

**세 번째가 다른 앱이 못 주는 것이다.** 나머지는 형태만 다를 뿐 경쟁자도 한다.

### 조용히 돌아가는 것 — 데이터 감사

**차별점이 아니라 위생 요건이다.** 화면 앞에 안 세운다. 그러나 없으면 숫자가 거짓말을 한다.

실측 데이터에서 발견한 함정 (전부 그럴듯한 숫자라 눈으로 안 걸림):

| 함정 | 놓치면 |
|---|---|
| '이체'를 수입·지출로 이중계상 | 509건 **912만원** 왜곡 |
| 지출이 **음수**로 저장됨 | 저축률 **24,305%** 출력 |
| 환불 = 타입 '지출' + **양수** 금액 | 36건, 오차 **143만원** |
| 수입·지출·순자산 산술 불일치 | **−1,136만원** (수입 누락 의심) |

이 상태로 "1억까지 8,461만원"을 말하면 **틀린 숫자로 인생 계획을 세우게 만든다.**
→ 원칙: **조용히 검증하고, 이상할 때만 말한다.**

## 3. 유저 경험

> **개발자용 절차와 유저용 절차는 다르다.** 혼동하지 말 것.
> - `docs/setup-gmail.md` (Google Cloud OAuth, 터미널) = **Python 참조 구현 전용.** 유저는 안 한다
> - `appsscript/verify.gs` = **개발 검증용.** 유저는 안 본다
> - 유저가 하는 건 아래 §3-1 세 조작이 전부다

### 3-1. 초기 설치 — 3조작 (목표 구조, **아직 미구현**)

> ⚠️ **지금은 이렇지 않다.** 현재는 개발자가 Apps Script 편집기에 파일을 직접
> 붙여넣고 스크립트 속성에 비밀번호를 손으로 넣는다. 아래는 **배포 시 목표**이고,
> 그 사이의 간극이 `DECISIONS.md`의 **D7(비밀번호 수집)** 과 **D8(배포 경로)** 다.
> 실사용자를 받으려면 반드시 풀어야 한다.

```
1. 링크 클릭 → "사본 만들기"
      배포물은 스크립트가 바인딩된 Google Sheet 하나다.
      링크가 .../copy 로 끝나므로 버튼 하나로 유저 Drive 에 복제된다.

2. 시트 메뉴 → "⚙️ 처음 설정하기" → 비밀번호 입력
      onOpen() 이 만든 커스텀 메뉴. 뱅샐 zip 비번을 받아
      PropertiesService(유저 계정 스코프)에 저장한다.
      같은 함수가 시간 트리거도 스스로 생성한다.

3. 권한 승인
      "Google에서 확인하지 않은 앱입니다" 경고 1회. 회피 불가.
```

**유저가 하지 않는 것**: Google Cloud 프로젝트 생성, OAuth 클라이언트 발급,
테스트 사용자 등록, 터미널 명령, 코드 붙여넣기, 트리거 수동 설정.

Apps Script 내장 서비스(GmailApp·DriveApp)는 **유저 OAuth 클라이언트를 요구하지 않는다.**
스크립트가 유저 계정에서 유저 권한으로 실행되기 때문이다.

### 3-2. 평소 사용

```
[유저가 하는 유일한 수동 조작]
  뱅크샐러드 앱 → 메뉴 → 설정 → 데이터 내보내기 → 파일로 받기
  → 이메일 확인 → 비밀번호 입력(매번 같은 값으로)
        ↓ (메일 도착)

[자동 — Google 서버에서, 노트북·폰 전원 무관]
  트리거 발동 → Gmail 검색 → zip → 복호화 → 파싱
  → 정규화 → 감사 → 집계 → Drive 저장 + heartbeat 갱신
        ↓
  알림: "8월 리포트 준비됨"
```

> ⚠️ **뱅샐 비밀번호는 매 내보내기마다 유저가 새로 설정한다.** 지난번과 다른 값을
> 넣으면 복호화가 실패한다. 그래서 **조용히 실패하면 안 된다** — 실패를 감지해
> "zip 비번이 다릅니다"를 메일로 알리고, 리마인더에 힌트(`0***0`)를 동봉한다.
> 마지막 성공 시각은 `heartbeat.json` 에 남아 리포트의 "마지막 갱신 N일 전"이 된다.

### 3-3. 대화 예시 — 어디서든, 아무 LLM으로나

```
유저: 1억까지 얼마나 남았어?
 AI:  8,461만원 남았습니다. 최근 3개월 평균 저축 페이스(월 42만원)로는
      2033년 3월 도달 예상입니다. 목표가 30세라면 약 2년 늦습니다.

유저: 이번 달 왜 초과했어?
 AI:  여행/숙박이 24만원으로 평소(2만원)의 12배입니다.
      참고로 7월 27일 철도 결제 5.3만원은 취소되어 이미 차감돼 있습니다.

유저: 구독 다 끊으면 얼마나 빨라져?
 AI:  월 7.9만원입니다. 전부 끊으면 도달 시점이 약 5개월 앞당겨집니다.
```

### 3-4. 진입 경로 — 마찰은 가치 이후에 청구한다

설치 3조작도 첫 사용자에겐 여전히 마찰이다. **가치를 먼저 보여주고 나중에 청구한다.**

| 단계 | 유저가 하는 것 | 얻는 것 | 포기하는 것 |
|---|---|---|---|
| **Tier 0** | zip 을 LLM 에 첨부 + 프롬프트 붙여넣기 (**설치 0, 3분**) | 리포트 전부 | 자동화 · 정기 푸시 |
| **Tier 1** | Sheet 사본 3조작 | 자동 갱신 · 모바일 · 시계열 | — |

**Tier 0 의 기술 근거 (실측 검증됨)**: 뱅샐 zip 은 ZipCrypto 이고 **Python 표준 `zipfile`
이 이를 복호화한다**(`setpassword()`; AES 만 미지원). `pyzipper` 없이 해제 → `openpyxl`
파싱까지 성공을 확인했다. → **LLM 코드 인터프리터 안에서 라이브러리 설치 없이 열린다.**

산수 신뢰성은 **계산 스크립트를 프롬프트에 동봉**해 지킨다
(*"반드시 이 코드를 실행하고 직접 산수하지 마라"*).

### 3-5. 남는 마찰과 완화

| 마찰 | 완화 |
|---|---|
| "확인되지 않은 앱" 경고 + **Gmail 전체 접근** 요구 | 회피 불가. 다만 Gmail 스코프를 빼고 기성 애드온으로 zip→Drive 이동하면 문구가 "Drive 파일"로 약해진다 |
| 첫 리포트까지 대기 | 첫 리포트를 **메일로** 보낸다. LLM 커넥터 연결을 설치 경로에서 제거 |
| 내보내기를 잊는다 (**리텐션의 급소**) | 마지막 zip 이후 N일 추적 → 리마인더. 비번 힌트 + 미끼("지난달 구독료 7.9만원이 나갔어요") |
| Apps Script 에디터 **모바일 미지원** | Tier 0 은 폰에서 완결. Tier 1 설치만 데스크톱 |
| 트리거가 **조용히 죽는다** | `heartbeat.json` 으로 마지막 실행 시각 기록 → 리포트에 "N일 전" 표시 |

## 4. 기술 스택

### 4-1. 실행 환경 — 전부 Google 서버

| 계층 | 기술 | 이유 |
|---|---|---|
| 실행 | **Google Apps Script** | 시간 트리거가 Google 서버에서 돈다 → **유저 기기 전원 무관**. 인프라 계정 불필요 |
| 메일 수집 | Apps Script **Gmail Service** | 내장. GCP OAuth 클라이언트 불필요 |
| zip 복호화 | **자체 ZipCrypto 구현** (`zipcrypto.gs`) | `Utilities.unzip()`은 암호 zip 불가. UnzipGs는 Rhino가 필요한데 2026-01-31 sunset |
| xlsx 파싱 | **Drive API로 Sheets 변환 후 `getValues()`** | 엑셀 파서 이식이 통째로 불필요해진다 |
| 저장 | Apps Script **Drive Service** | 유저 개인 저장소. 우리 서버 없음 |
| 시크릿 | **Properties Service** | 코드·리포지토리에 비번이 남지 않는다 |

### 4-2. 코어 — 한 벌로 양쪽에서 돈다

**포팅 단계가 없다.** node로 검증한 **같은 파일**이 Apps Script에서 실행된다.
두 구현을 따로 두면 반드시 어긋나고, 어긋난 걸 알아채는 데 오래 걸린다.

```
core/model.js      부호 규약 · 소유자 판정 · 스냅샷 파생값
core/layout.js     뱅샐 레이아웃 ← 앱 형식이 바뀌면 여기만 고친다
core/analyze.js    집계
core/parse.js      시트 행 → 도메인 객체
core/aggregate.js  Drive에 올릴 facts JSON
       │
       │  node scripts/build-gs.js   (의존 순서대로 한 파일로 묶는다)
       ▼
appsscript/core.gs
```

> **왜 묶는가**: Apps Script는 파일 간 전역 실행 순서를 보장하지 않는다.
> 모듈이 로드 시점에 `KM.model`을 참조하므로 순서가 어긋나면 조용히
> `undefined`가 되고, 죽지 않은 채 이상한 값을 낸다.

| 도구 | 용도 |
|---|---|
| node ≥ 20 | 코어 실행·테스트. 의존성 0 |
| `node --test` | 회귀 테스트 40개 |
| Python + `uv` | **개발 도구만.** Gmail 탐색, 테스트 픽스처 생성 |

### 4-3. 클라이언트 (유저가 대화하는 곳)

| 방식 | 검증 | 비고 |
|---|---|---|
| **Google Drive 커넥터** — Claude | ✅ **실측 확인** | 주 경로 |
| Drive 커넥터 — ChatGPT · Gemini | ❓ 미검증 | ChatGPT는 Plus 이상 전용 |
| MCP 서버 (로컬) | — | **선택.** 데스크톱에서 정교한 시뮬레이션이 필요할 때 |

> **왜 MCP가 주 경로가 아닌가**: `claude.ai` 웹과 ChatGPT 웹·모바일은 **로컬 MCP(stdio)에
> 접근할 수 없다.** 웹에서 쓰려면 인터넷에 노출된 원격 서버가 필요하고, 그건 호스팅
> 비용이거나 배포 마찰이다. **인제스트가 진짜 자동이면 대화로 트리거할 이유가 없다.**

## 5. 기술 파이프라인

**전 구간 1회 실행 = 14초.** 아래는 실측 검증된 흐름이다.

```
┌──────────────────────────────────────────────────────────────┐
│  ① 수집     Gmail 검색 → 첨부 zip → Drive/raw/ 에 원본 보존    │
│             처리한 message id 를 기록해 같은 메일을 다시 안 본다│
├──────────────────────────────────────────────────────────────┤
│  ② 복호화   ZipCrypto 자체 구현으로 해제 (550ms)               │
│             복호화한 스트림으로 무암호 zip 을 재조립해          │
│             Utilities.unzip() 에 넘긴다 (inflate 가 네이티브)   │
│             재조립 시 UTF-8 플래그를 세워 한글 파일명도 복원     │
├──────────────────────────────────────────────────────────────┤
│  ③ 변환     Drive API 로 xlsx → Google Sheets                 │
│             엑셀 파서 이식이 통째로 사라지는 지점               │
├──────────────────────────────────────────────────────────────┤
│  ④ 파싱     getValues() → 거래·잔고 객체                       │
│             헤더가 다르면 **즉시 실패** ← 조용히 틀리지 않게     │
│             합계 셀은 읽지 않는다 (수식이라 값이 없다)          │
├──────────────────────────────────────────────────────────────┤
│  ⑤ 정규화   · '이체' 분리 (수입/지출 합산에서 제외)             │
│             · 부호 규약 (지출 음수 → outflow 로 반전)          │
│             · 환불 = 지출 타입 + 양수 → 차감                   │
│             · 원화 아닌 거래는 합계에서 제외                    │
├──────────────────────────────────────────────────────────────┤
│  ⑥ 집계     월별 수지 · 카테고리 · 고정지출 · 급증 · 유휴현금   │
│             투자 손익 · **이체를 본인/타인으로 분해**           │
├──────────────────────────────────────────────────────────────┤
│  ⑦ 품질     dataQuality.flags — 판단이 아니라 **신호**         │
│             못 믿을 값은 키 자체를 만들지 않는다 (저축률)       │
├──────────────────────────────────────────────────────────────┤
│  ⑧ 델타     이전 스냅샷과 비교                                 │
│             대화 한 세션이 알 수 없는 유일한 것                 │
├──────────────────────────────────────────────────────────────┤
│  ⑨ 산출     facts-YYYY-MM-DD.json + latest.json               │
└──────────────────────────────────────────────────────────────┘
                              ↓
              Claude / ChatGPT / Gemini 가 Drive 를 읽고 대화
```

### 산출물 레이아웃

```
Drive/k-money/
├── latest.json              LLM이 읽는 것. 고정 이름이라 커넥터가 찾기 쉽다
├── facts-YYYY-MM-DD.json    히스토리 (최근 12개). 델타 계산의 재료
├── status.json              마지막 실행 결과. 실패도 여기 남는다
└── raw/YYYY-MM-DD.zip       원본 보존 — 집계를 고쳤을 때 소급 재계산용
```

### 설계 원칙: 집계는 우리가, 발견은 LLM이

한때 감사 규칙 엔진(R1~R8 + 한국어 문장)이 있었다. **지웠다.**

규칙의 가치는 문장이 아니라 **"무엇을 계산할지 고른 것"** 이었다.
거래 2,456건을 그대로 던지면 LLM은 이체의 비대칭을 못 찾지만,
`transfers.external.net = 8,917,889`을 보여주면 **당연히** 알아챈다.
그건 판단이 아니라 집계다.

| 우리 | LLM |
|---|---|
| 모든 산수와 파생값 | 무엇이 문제인지 |
| 이체를 본인/타인으로 분해 | "수입으로 안 잡힌 돈이 있네요" |
| 데이터 품질 신호 | 문장·어투·순서 |
| 시계열 델타 | 유저 질문에 대한 답 |

**LLM이 계산하게 두지 않는다.** 필요한 파생값을 전부 미리 넣는다.
**못 믿을 값은 넣지 않는다.** `null`이 아니라 키 자체를 없앤다 — 없는 숫자는
인용될 수 없다. 우리는 유저의 프롬프트를 소유하지 않으므로 **파일 자체가
유일한 방어 수단**이다.

## 7. 설계 원칙

| 원칙 | 내용 |
|---|---|
| **계산은 코드, 해석은 LLM** | 함정은 코드로 못 박는다. LLM은 확정된 숫자만 읽는다 |
| **조용히 검증** | 감사는 위생 요건. 이상할 때만 말한다 |
| **팔 게 없다** | 무료 OSS. 상품 추천도 광고도 없다 — **권유 자체가 없다** |
| **데이터는 유저 것** | 우리 서버 없음. 유저의 Gmail·Drive에만 있고, 파일로 소유한다 |
| **조용히 틀리지 않는다** | 스키마가 바뀌면 즉시 실패. 틀린 리포트보다 낫다 |
| **자문 안 함** | 사실·계산·비교까지. 처방은 안 한다 (`docs/product.md` §5) |

### 왜 무료여야 하는가

기존 서비스는 **어딘가에서 반드시 수익화 지점을 보여야 한다** — 뱅샐은 대출·카드·보험
중개 수수료, 카카오페이는 투자권유까지 확대 예고, 무료 앱은 광고, 로보어드바이저는
수익금의 연 9.5%.

**우리는 파이프라인을 만들어 배포할 뿐이라 그 지점이 없다.**
그리고 개인화된 금융 조언에 대가를 받는 순간 **투자자문업 인가 영역**으로 넘어간다.
무료는 선택이 아니라 구조다.

## 개발

```sh
npm test              # 회귀 테스트 40개 (의존성 0, node ≥ 20)
npm run build         # core/ → appsscript/core.gs 로 묶는다
npm run check         # build + test

# 실데이터로 산출물을 만들어 본다 (픽스처 필요)
uv run python scripts/dump-rows.py <내보낸.xlsx> fixtures/real.json
node scripts/run-local.js fixtures/real.json
```

Apps Script 쪽 함수:

| 함수 | 용도 |
|---|---|
| `setup_check()` | 비밀번호·core·Drive API·Gmail 준비 상태 점검 |
| `runOnceForce()` | 지금 한 바퀴 돌린다 (처리 이력 무시) |
| `install_dailyTrigger()` | 매일 오전 7시 자동 실행 |
| `probe_formats()` / `probe_cleanup()` | 커넥터 포맷 탐침 (**가짜 숫자만**) |

> ⚠️ `.env`, `secrets/`, `data/`, `fixtures/` 는 gitignore 된다.
> **금융 데이터와 시크릿을 커밋하지 말 것.** `fixtures/real.json`에는 거래 전량이 들어 있다.
>
> ⚠️ zip 비밀번호는 **코드에 적지 않는다.** Apps Script 프로젝트 설정의
> 스크립트 속성(`BANKSALAD_ZIP_PASSWORD`)에 넣는다. 코드에 적으면 편집 이력에
> 남고 프로젝트를 복사·공유하는 순간 같이 나간다.
