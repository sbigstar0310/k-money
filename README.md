# money-audit

> **1억, 진짜로 가능한지 네 숫자로 알려준다.**
>
> 뱅크샐러드가 내보낸 실제 금융 데이터를 물려서 목표까지의 거리를 계산하고,
> 페이스가 어긋나면 알려주고, 무엇이든 물어보게 한다.
> 데이터는 유저가 소유하고, 우리는 아무것도 팔지 않는다.

---

## 1. 누구를 위한 것인가

**LLM은 익숙한데 돈 관리는 처음인 사회 초년생.**

- ChatGPT·Claude를 매일 쓴다. AI에게 물어보는 게 자연스럽다
- 최근 자산관리에 관심이 생겼다 (첫 직장, 첫 목돈, 주변의 "1억" 이야기)
- 금융 지식은 얕고, 앱이 주는 요약은 무슨 뜻인지 잘 모른다

**핵심 간극**: 이미 AI에게 뭐든 물어보지만, **자기 실제 금융 데이터로는 못 물어본다.**
"ChatGPT한테 물어보면 되지 않나?"는 맞는 직감인데, 데이터를 못 물려서 일반론만 돌아온다.

### 해결하려는 문제

| | 문제 |
|---|---|
| **P1** | "30세에 1억이라는데, 어떻게 모으는지 모르겠다." 목표는 있는데 자기 상황에서 가능한 숫자인지 모른다. 검색하면 일반론만 나온다 |
| **P2** | "내 소비 패턴을 보고 현실적인 피드백을 받고 싶다." 월말 요약은 받는데 그래서 뭘 하라는 건지 모르고, 알림은 다 쓰고 난 뒤에 온다 |

**아닌 사람**: 예산 세우고 지키는 훈련이 목적인 사람 (→ 카카오페이 AI코치, Actual Budget).

## 2. 무엇을 해주나

| 층 | 무엇 | 주기 |
|---|---|---|
| **목표** | 1억까지 얼마 남았고, 현재 페이스면 언제 도달하는가 | 갱신 시 |
| **페이스** | 이번 달 소비가 목표 대비 어디쯤인가 | 주 1회 (→ 향후 일 단위) |
| **대화** | "왜 이번 달은 초과했어?" "이거 줄이면 얼마나 빨라져?" | 언제든 |

**세 번째가 다른 앱이 못 주는 것이다.** 나머지는 형태만 다를 뿐 경쟁자도 한다.

### 조용히 돌아가는 것 — 데이터 감사

**차별점이 아니라 위생 요건이다.** 화면 앞에 안 세운다. 그러나 없으면 숫자가 거짓말을 한다.

실측 데이터에서 발견한 함정 (전부 그럴듯한 숫자라 눈으로 안 걸림):

| 함정 | 놓치면 |
|---|---|
| '이체'를 수입·지출로 이중계상 | 509건 **912만원** 왜곡 |
| 지출이 **음수**로 저장됨 | 저축률 **24,305%** 출력 |
| 환불 = 타입 '지출' + **양수** 금액 | 36건, 오차 **143만원** |
| 수입·지출·순자산 산술 불일치 | **−1,136만원** (수입 누락 의심) |

이 상태로 "1억까지 8,461만원"을 말하면 **틀린 숫자로 인생 계획을 세우게 만든다.**
→ 원칙: **조용히 검증하고, 이상할 때만 말한다.**

## 3. 유저 경험

> ⚠️ **이 절은 적대적 리뷰(2026-08-08)에서 반박되어 재작성 대기 중이다.**
> 확인된 오류:
> - **1단계(Google Cloud OAuth)는 불필요하다.** Apps Script 내장 서비스는 유저 OAuth
>   클라이언트를 요구하지 않는다. Python 참조 구현의 설치 절차를 유저 절차에 잘못 넣었다.
>   이 한 단계가 추정 완주율을 4%↔17%로 4배 가른다
> - **"탭 3번"은 사실이 아니다.** 실제 뱅샐 흐름은 홈 → 메뉴 → 설정 → 데이터 내보내기 →
>   파일로 받기 → 이메일·**비밀번호 입력**
> - **"약 10분"도 사실이 아니다.** 원자 단위로 22개 조작, 최상의 경우 35분
> - **미확인 실패 모드**: 비밀번호를 매 내보내기마다 설정한다면, 유저가 지난번과 다른 값을
>   넣는 순간 파이프라인이 **조용히 실패**한다
>
> 대체 설계는 §3-4 참조.

### 3-1. 초기 설치 (1회, 약 10분) — 반박됨

| # | 단계 | 하는 일 |
|---|---|---|
| 1 | **Google Cloud 설정** | 프로젝트 생성 → Gmail API 사용 설정 → OAuth 클라이언트(데스크톱 앱) 발급 → 테스트 사용자에 본인 추가 (`docs/setup-gmail.md`) |
| 2 | **Apps Script 배포** | script.google.com 새 프로젝트 → 스크립트 붙여넣기 → Google 계정 승인 |
| 3 | **비밀번호 1회 입력** | 뱅샐 내보내기 zip 비번을 Apps Script 속성에 저장 (유저 계정 스코프, 코드에 안 남음) |
| 4 | **트리거 설정** | 시간 기반 트리거 (예: 매일 오전 8시). 새 메일이 없으면 아무것도 안 한다 |
| 5 | **LLM 연결** | Claude / ChatGPT / Gemini에 **Google Drive 커넥터** 연결 |

> 설치 후에는 이 화면들을 다시 볼 일이 없다.

### 3-2. 평소 사용

```
[유저가 하는 유일한 수동 조작]
  폰에서 뱅크샐러드 앱 → 데이터 내보내기 → 탭 3번
        ↓ (메일 도착)

[자동 — Google 서버에서, 노트북·폰 전원 무관]
  트리거 발동 → Gmail 검색 → zip 다운로드 → 비번 해제
  → xlsx 파싱 → 정규화 → 감사 → 집계 → Drive 저장
        ↓

[유저]
  푸시 알림: "8월 리포트 준비됨"
```

### 3-3. 대화 예시 — 어디서든, 아무 LLM으로나

```
유저: 1억까지 얼마나 남았어?
 AI:  8,461만원 남았습니다. 최근 3개월 평균 저축 페이스(월 42만원)로는
      2033년 3월 도달 예상입니다. 목표가 30세라면 약 2년 늦습니다.

유저: 이번 달 왜 초과했어?
 AI:  여행/숙박이 24만원으로 평소(2만원)의 12배입니다.
      참고로 7월 27일 철도 결제 5.3만원은 취소되어 이미 차감돼 있습니다.

유저: 구독 다 끊으면 얼마나 빨라져?
 AI:  월 7.9만원(Claude 3.9만 · ChatGPT 1.8만 · MS · 라프텔 · 쿠팡와우)입니다.
      전부 끊으면 도달 시점이 약 5개월 앞당겨집니다.

유저: 지금 통장에 놀고 있는 돈 있어?
 AI:  자유입출금 856만원 중 달달 하나 통장에 662만원이 있습니다.
      현재 파킹통장 금리 구간은 연 2.5~3.0%입니다(finlife 공시 기준).
      ※ 어떤 상품을 선택할지는 직접 판단하세요. 이 도구는 자문을 하지 않습니다.
```

### 3-4. 대체 설계 — 마찰을 가치 이후로 미룬다 (검증됨, 2026-08-08)

**핵심 원칙: 가치를 이미 경험한 뒤에 마찰을 청구한다.**
현재 §3-1은 정반대로, 가치를 보기 전에 마찰을 전액 선불로 받는다.

#### Tier 0 — 설치 0, 3분 ★ 진입 경로

```
1. 뱅샐 앱 → 내보내기 → 메일 도착        (어차피 모든 경로가 필요로 한다)
2. 폰에서 메일의 zip을 ChatGPT/Claude에 첨부 + 프롬프트 붙여넣기
3. 5초 뒤 리포트
```

**기술 근거 (실측 검증 완료)**: 뱅샐 zip은 ZipCrypto이고, **Python 표준 `zipfile`이
ZipCrypto 복호화를 지원한다**(`setpassword()`; AES만 미지원). 실제로 `pyzipper` 없이
표준 라이브러리만으로 해제 → `openpyxl` 파싱까지 성공을 확인했다.
→ **코드 인터프리터 안에서 라이브러리 설치 없이 바로 열린다.**

**산수 신뢰성은 어떻게 지키나**: 계산 스크립트를 프롬프트에 동봉하고
*"반드시 이 코드를 실행해서 계산하라, 직접 산수하지 말라"* 고 지시한다.
코드 인터프리터가 결정론적으로 돌리므로 함정 3종이 재발하지 않는다.

**포기하는 것**: 자동화, 정기 푸시. 시계열은 프로젝트 파일 누적으로 부분 확보.
프라이버시는 **Tier 1도 최종적으로 Drive 커넥터를 통해 동일하게 클라우드로 가므로 실질 차이 없음.**

#### Tier 1 — Sheet 사본 1클릭 (3조작)

자동화가 필요해진 유저를 위한 다음 단계. **GCP 설정 없음.**

```
1. 링크 클릭 → "사본 만들기"            (스크립트가 바인딩된 Google Sheet)
2. 시트 메뉴 → "처음 설정하기" → 비번 입력
3. 권한 승인                             (경고 화면 1회, 회피 불가)
   → 트리거는 스크립트가 스스로 생성한다
```

부수 효과: **시트 자체가 대시보드다.** 코드는 못 읽어도 표는 읽는다.

#### 남는 마찰과 완화

| 마찰 | 완화 |
|---|---|
| "확인되지 않은 앱" 경고 + **Gmail 전체 접근** 요구 | Gmail 스코프를 빼고 기성 애드온(Save Emails and Attachments)으로 zip→Drive 이동. 경고 문구가 "Gmail 메시지 및 설정 보기"에서 "Drive 파일"로 약해진다 |
| 첫 리포트까지 최대 24시간 | 첫 리포트를 **메일로** 보낸다. LLM 커넥터 연결을 설치 경로에서 제거 |
| 내보내기를 잊는다 (리텐션의 급소) | 마지막 zip 이후 N일 추적 → 리마인더. **비번 힌트 동봉**(조용한 실패 방지) + 미끼("지난달 구독료 7.9만원이 나갔어요") |
| Apps Script 에디터 **모바일 미지원** | Tier 0은 폰에서 완결된다. Tier 1 설치만 데스크톱 |

## 4. 기술 스택

### 4-1. 자동 파이프라인 (V1 — 목표 구조)

| 계층 | 기술 | 이유 |
|---|---|---|
| 실행 환경 | **Google Apps Script** | Google 서버에서 시간 트리거로 실행 → **유저 기기 전원 무관**. 인프라 계정 불필요 |
| 메일 수집 | Apps Script **Gmail Service** | 내장. OAuth 별도 구현 불필요 |
| zip 복호화 | **UnzipGs** (→ zlib.js) 또는 **자체 ZipCrypto 구현** | `Utilities.unzip()`은 암호 zip 불가. zlib.js가 ZipCrypto 지원 (AES 미지원, **우리 파일은 ZipCrypto**) |
| 저장 | Apps Script **Drive Service** | 유저 개인 저장소. 우리 서버 없음 |
| 시크릿 | **Properties Service** | 유저 계정 스코프. 코드·리포지토리에 비번이 남지 않음 |
| 알림 | Gmail / Drive 알림 | 추가 인프라 없음 |

### 4-2. 참조 구현 (현재 — 검증 완료, Python)

Apps Script 구현의 **스펙이자 검증 기준**. 실데이터 회귀 테스트에 쓴다.

| 목적 | 패키지 |
|---|---|
| 런타임 | Python 3.11+, `uv` |
| Gmail API | `google-api-python-client`, `google-auth-oauthlib` (스코프: `gmail.readonly`) |
| zip 복호화 | `pyzipper` (ZipCrypto + AES 양쪽) |
| xlsx 파싱 | `openpyxl` (read-only 모드) |
| 설정 | `python-dotenv` |

### 4-3. 클라이언트 (유저가 대화하는 곳)

| 방식 | 지원 | 비고 |
|---|---|---|
| **Google Drive 커넥터** | Claude · ChatGPT · Gemini (웹·모바일 전부) | **주 경로.** 설치 마찰 최소 |
| MCP 서버 (로컬) | Claude Desktop/Code, Cursor, Codex | **선택.** 데스크톱에서 정교한 시뮬레이션이 필요할 때 |

> **왜 MCP가 주 경로가 아닌가**: `claude.ai` 웹과 ChatGPT 웹·모바일은 **로컬 MCP(stdio)에
> 접근할 수 없다.** 유저 기기에서 프로세스를 띄울 수 없기 때문. 웹에서 MCP를 쓰려면
> 인터넷에 노출된 원격 서버가 필요하고, 그건 호스팅 비용이거나 배포 마찰이다.
> **인제스트가 진짜 자동이면 대화로 트리거할 이유가 없고**, 조회·대화는 Drive 커넥터로 충분하다.

## 5. 기술 파이프라인

```
┌──────────────────────────────────────────────────────────────┐
│  ① 수집        Gmail 검색 → 첨부 zip 다운로드                   │
│                재처리 방지: 처리한 message_id 기록              │
├──────────────────────────────────────────────────────────────┤
│  ② 복호화      ZipCrypto 해제                                  │
│                한글 파일명 복원 (UTF-8 플래그 없는 zip → CP437  │
│                오독을 UTF-8/CP949로 재디코딩)                   │
├──────────────────────────────────────────────────────────────┤
│  ③ 파싱        xlsx 2시트                                      │
│                · '가계부 내역'  10컬럼 정형 표 (헤더 1행)        │
│                · '뱅샐현황'    6섹션 비정형 (자산·투자·대출)     │
│                헤더 불일치 시 즉시 실패 ← 조용히 틀리지 않게     │
├──────────────────────────────────────────────────────────────┤
│  ④ 정규화      · '이체' 분리 (수입/지출 합산에서 제외)          │
│                · 부호 규약 (지출 음수 → outflow 로 반전)        │
│                · 환불 처리 (지출 타입 + 양수 = 차감)            │
├──────────────────────────────────────────────────────────────┤
│  ⑤ 감사        · 수입/지출/순자산 산술 정합성                   │
│                · 미분류 비율, 연동 끊긴 계좌 추정               │
│                · 이상치 (평소 대비 급증 카테고리)               │
├──────────────────────────────────────────────────────────────┤
│  ⑥ 집계        · 월별 수입·지출·순저축·저축률                   │
│                · 고정/변동 분해 (3개월 이상 반복 + 변동폭 ≤15%) │
│                · 대분류·결제수단별 집계                         │
├──────────────────────────────────────────────────────────────┤
│  ⑦ 스냅샷      계좌별 잔액 · 종목별 원금/평가/수익률            │
│                날짜별 적립 → 시계열 (뱅샐은 1년치만 준다)       │
├──────────────────────────────────────────────────────────────┤
│  ⑧ 목표        목표액·목표시점 대비 현재 위치                   │
│                현재 페이스 기준 도달 시점 역산                  │
├──────────────────────────────────────────────────────────────┤
│  ⑨ 산출        Drive 에 JSON(기계용) + Markdown(사람용) 저장    │
└──────────────────────────────────────────────────────────────┘
                              ↓
              Claude / ChatGPT / Gemini 가 Drive 를 읽고 대화
```

### 산출물 레이아웃

```
Drive/money-audit/
├── report-YYYY-MM-DD.md        사람이 읽는 리포트
├── snapshot-YYYY-MM-DD.json    계좌별 잔액, 종목별 손익
├── ledger-summary.json         월별 집계 (계산 완료)
├── goal-progress.json          목표 대비 위치·도달 시점
├── audit-findings.json         감사 결과
└── raw/                        원본 zip 보존 (소급 재처리용)
```

### 설계 원칙: 계산은 코드가, 해석은 LLM이

LLM에게 원본 거래 2,456건을 던지면 **④의 함정 세 개를 매번 새로 밟는다** —
실제로 개발 중 세 번 다 틀렸다. 그래서 **파이프라인이 계산까지 끝내고,
LLM은 이미 확정된 숫자를 읽고 해석·대화만 한다.**

이렇게 하면 **산수 신뢰성**과 **자유 대화**를 동시에 얻고, 토큰도 절약된다.

### 시트 `가계부 내역` — 정형, 헤더 1행

| 컬럼 | 타입 | 비고 |
|---|---|---|
| 날짜 | datetime | |
| 시간 | time | |
| 타입 | str | **수입 / 지출 / 이체** 3종 |
| 대분류 / 소분류 | str | 24종 / 64종 |
| 내용 | str | 가맹점명 |

| 화폐 | str | KRW |
| 결제수단 | str | 17종 |
| 메모 | str | **항상 비어 있음** |

| 섹션 | 내용 |
|---|---|
| 1. 고객정보 | 이름, 성별 |
| 2. 현금흐름현황 | 항목/총계/월평균 + 월별 13컬럼 |

| 4. 보험현황 | |
| 5. **투자현황** | 종목별 투자원금 · 평가금액 · 수익률 |
| 6. 대출현황 | |

> **토스증권 Open API가 불필요한 이유**: 5번 섹션에 종목별 손익이 이미 다 있다.
> 이 서비스는 주문을 내지 않고 readonly 조회만 필요하다.
> 없는 것: 예수금 상세, 매수/매도 거래 내역.

## 7. 설계 원칙

| 원칙 | 내용 |
|---|---|
| **계산은 코드, 해석은 LLM** | 함정은 코드로 못 박는다. LLM은 확정된 숫자만 읽는다 |
| **조용히 검증** | 감사는 위생 요건. 이상할 때만 말한다 |
| **팔 게 없다** | 무료 OSS. 상품 추천도 광고도 없다 — **권유 자체가 없다** |
| **데이터는 유저 것** | 우리 서버 없음. 유저의 Gmail·Drive에만 있고, 파일로 소유한다 |
| **조용히 틀리지 않는다** | 스키마가 바뀌면 즉시 실패. 틀린 리포트보다 낫다 |
| **자문 안 함** | 사실·계산·비교까지. 처방은 안 한다 (`docs/product.md` §5) |

### 왜 무료여야 하는가

기존 서비스는 **어딘가에서 반드시 수익화 지점을 보여야 한다** — 뱅샐은 대출·카드·보험
중개 수수료, 카카오페이는 투자권유까지 확대 예고, 무료 앱은 광고, 로보어드바이저는
수익금의 연 9.5%.

**우리는 파이프라인을 만들어 배포할 뿐이라 그 지점이 없다.**
그리고 개인화된 금융 조언에 대가를 받는 순간 **투자자문업 인가 영역**으로 넘어간다.
무료는 선택이 아니라 구조다.
